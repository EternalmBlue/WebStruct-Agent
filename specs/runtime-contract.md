# 统一运行契约

状态：已实施的运行契约；关联验收：extraction、evaluation、observability、UI。

## 任务、节点与质量

| 层次 | 状态或结论 | 含义 |
| --- | --- | --- |
| 任务 | queued、running、completed、failed | 排队、执行中、流程完成、流程无法完成 |
| 节点 | pending、running、success、failed、skipped | 未开始、执行中、正常结束、节点异常、按策略未执行 |
| 字段 | extracted、missing、repaired、fallback_failed | 保留已有字段状态，与任务状态分开 |
| 验证 | passed 与问题列表 | 质量结论，不替代任务或节点状态 |
| 客户端 | idle、refreshing、stale、offline 等展示状态 | 只表示本地交互或数据新鲜度，不改写服务端任务状态 |

正常任务流转为 `queued -> running -> completed`；致命异常流转到 `failed`。
终态不可因迟到的节点事件退回 running。重启可把中断的 queued/running 直接转为 failed。

字段缺失、证据不足或字段修复失败若已经产生可解释的最终结果和验证报告，不是工作流崩溃；
任务仍可 completed。采集失败、Schema 无法生成、必要存储失败等导致流程无法完成时为 failed。

无需修复时 `repair_agent_node` 是 skipped，不得伪造修复 success。上游失败后未执行的节点
是 skipped，说明原因；`result_persist_node` 可以执行失败结果留存，不覆盖原失败状态。

## 标识与进度

- `task_id` 唯一标识一次运行，`correlation_id` 关联原运行、重试及同一请求链路操作。
- 重试有新 task_id、原任务标识和同一 correlation_id；原记录不可覆盖。
- 嵌套运行增加 `parent_task_id`，必要时用事件关联其所属样本和评测方法。
- 根抽取图总节点数为 9，根评测图为 5；嵌套抽取不累加到父评测图的节点总数。
- `current_node` 可空：queued、终态或节点切换之间没有执行节点。
- `completed_node_count` 统计 success/skipped，不把 failed 或 running 当作已成功执行。
- 进度仅表示节点处理进展，不是正确率；任务完成时所有节点终结且进度达 100%，失败时保留实际进度。
- 状态时间使用带时区的 ISO 8601 时间；耗时以单调计时测量，前端按本地时区展示时间。

## 提交与查询

| 入口 | 结果 |
| --- | --- |
| POST /api/extract | 输入通过校验并创建任务元数据后返回 HTTP 202、task_id、correlation_id、queued 回执 |
| POST /api/benchmark/run | 同上，不等待最终报告 |
| GET /api/runs/{task_id} | HTTP 200，返回最新状态、当前节点、进度、更新时间与事件游标 |
| GET /api/runs/{task_id}/events | HTTP 200，返回事件及下一游标，可传 after_cursor 获取增量 |
| GET /api/extract/{task_id} | 非终态 HTTP 202；终态 HTTP 200，包含最终状态、结果或部分结果和错误 |
| GET /api/benchmark/reports/{task_id} | 非终态 HTTP 202；终态 HTTP 200，包含报告或失败上下文 |
| GET /api/observability/summary | HTTP 200，返回指定时间窗口的根任务统计，子任务默认不重复计入 |

不存在的任务返回 HTTP 404；格式、显式 Schema 或评测样本不合法返回 HTTP 422，不创建任务。
只有 URL 且模型未配置的请求仍可被接收，采集后在 Schema 节点明确失败并保留完整原因。
提交回执是创建时的快照；极快任务查询时已终结不改变原回执，也不要求人为延迟任务。

接受任务前必须先保存可追踪元数据，未能保存时明确返回服务错误，不能返回无法回查的成功回执。
同一次 UI 提交仅发一次请求；用户明确重试产生新任务。本轮不承诺分布式调度、断点续跑或全局 exactly-once。

## 事件语义

- 事件至少包含 task_id、correlation_id、顺序号、事件类型、时间、脱敏摘要。
- 节点事件还包含节点名、角色、状态与需要的上下文；结束事件补充结束时间和耗时。
- 开始事件立刻可查询，不能等节点结束后才第一次发布。结束前 end_time 和最终 runtime_ms 为空。
- skipped 节点说明原因，不伪造开始时间；终态事件记录任务总耗时、最终状态和安全的错误信息。
- 同一任务按递增顺序号排序，不能只用可能相同的时间戳排序。
- 游标代表最后已读顺序号；无新事件时返回空列表和原游标，分页不能丢失中间事件。
- 状态快照里的最新游标不代表客户端已消费事件；客户端只推进实际读到的游标。
- 客户端按事件标识去重，并避免较旧状态响应覆盖较新的终态。

## 恢复与留存

- 页面的任务标识保存在可恢复的地址或客户端状态里，不把凭据和完整配置写入客户端。
- 刷新页面后查询原任务，运行中继续刷新，终态回查结果，不重新提交。
- 本地后端重启识别遗留中断任务并写入 failed 与中断原因，不自动重复执行外部调用。
- 任务状态、事件、最终摘要是监测所需的最小留存；完整网页和业务视图属于独立业务留存。
- 关闭完整业务载荷留存不能让任务失去状态回查；没有足够输入的任务不能声称可直接重试。
- 重试使用原有业务输入与非敏感配置快照，实际密钥在运行时从当前 TOML 获取，不保存到任务记录。

## 界面与配置

首版可以用可配置短轮询实现自动刷新；契约不绑定轮询或 SSE。任务终态停止该任务轮询，
系统连接状态独立刷新。错误时标记数据陈旧并保留更新时间，不把网络中断当任务失败。

创建模式保留确定性规则优先与验证后修复的混合链路；没有模型可生成确定性 ProgramSpec，
字段级 fallback 如被启用但不可调用，应明确失败。运行已验证规则时修复默认关闭，
显式启用后只修复问题字段，原规则不变。

配置、日志和任务数据只保存非敏感配置标识或摘要，密钥、许可和数据库密码不得进入 Trace 或公开响应。
